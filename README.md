# xui-reseller

پنل نمایندگان (ادمین‌های فروش) برای پنل **ثنایی (MHSanaei/3x-ui)**، با الهام از بخش Admins پاسارگاد.
ثنایی دست‌نخورده می‌ماند؛ این سرویس جدا روی همان VPS اجرا می‌شود و از API ثنایی استفاده می‌کند.

## امکانات
- مالک (sudo): ساخت/ویرایش/حذف/غیرفعال‌سازی ادمین، و دیدن همه کاربران
- هر ادمین: یوزر و پسورد مخصوص خودش
- محدودیت هر ادمین: سقف تعداد کاربر، سقف کل حجم (مجموع حجم تخصیص‌یافته به کاربرانش)، تاریخ انقضای حساب، اینباندهای مجاز
- ادمین فقط کاربران خودش را می‌بیند: ساخت، ویرایش حجم/زمان، ریست ترافیک، فعال/غیرفعال، حذف، کپی لینک ساب
- وقتی ادمین غیرفعال یا منقضی شود، کاربرانش خودکار غیرفعال می‌شوند و با فعال‌سازی دوباره برمی‌گردند (هر ۵ دقیقه همگام‌سازی)
- پروتکل‌های پشتیبانی‌شده: vless، vmess، trojan

## نصب
```bash
git clone https://github.com/USER/xui-reseller.git
cd xui-reseller
sudo bash install.sh
```
اسکریپت آدرس/یوزر/پسورد ثنایی را می‌پرسد و سرویس systemd می‌سازد. دوباره اجرای آن، فایل‌ها را آپدیت می‌کند و `.env` را نگه می‌دارد.

## تنظیمات (`/opt/xui-reseller/.env`)
| متغیر | توضیح |
|---|---|
| PANEL_URL | آدرس ثنایی همراه با webBasePath، مثلاً `http://127.0.0.1:2053/abcd` |
| PANEL_USER / PANEL_PASS | ورود به ثنایی |
| SUDO_USER / SUDO_PASS | ورود مالک به این پنل |
| SUB_URL_BASE | مثلاً `https://domain:2096/sub/` (آدرس + subId لینک ساب را می‌سازد) |
| PORT | پورت (پیش‌فرض 8088) |
| COOKIE_SECURE | اگر پشت HTTPS هستید `1` کنید |

پس از تغییر: `systemctl restart xui-reseller`

## نکات
- ثنایی باید ساب‌اسکریپشن فعال داشته باشد تا لینک اشتراک کار کند.
- ورود دومرحله‌ای (2FA) ثنایی پشتیبانی نمی‌شود؛ برای حساب API غیرفعالش کنید.
- حجم ادمین بر اساس «مجموع حجم تخصیص‌یافته» حساب می‌شود، نه مصرف واقعی؛ این جلوی فروش بیش از سهمیه را می‌گیرد.
- مسیرهای API ثنایی در نسخه‌های مختلف ممکن است کمی فرق کنند. اگر خطا دیدید: `journalctl -u xui-reseller -f`
- پنل را پشت HTTPS (nginx/caddy) بگذارید یا با تونل SSH استفاده کنید.
